# Tyrminal v0.1.0-beta.1 — pre-release

> **This is a pre-release for testing, not a stable or production-ready version.**
> It has **not been independently security reviewed**. The installers are **unsigned**. Use it
> with test servers and test credentials. There is no automatic updater.

Tyrminal is a local-first SSH client: an encrypted vault on your device, verified host keys,
and a modern terminal. No account, no cloud, no telemetry.

### Opening an unsigned build

- **macOS:** the app is not notarized. After copying it to Applications, right-click (or
  Control-click) Tyrminal → **Open** → **Open**. If macOS still refuses: System Settings →
  Privacy & Security → "Tyrminal was blocked" → **Open Anyway**.
- **Windows:** SmartScreen shows "Windows protected your PC". Click **More info** →
  **Run anyway**. The installer installs for the current user only. WebView2 is required (it
  is part of Windows 10/11; the installer offers to download it if missing).
- **Linux:** `sudo apt install ./tyrminal-v0.1.0-beta.1-linux-x64.deb`, or
  `chmod +x tyrminal-v0.1.0-beta.1-linux-x64.AppImage` and run it.
  WebKitGTK 4.1 is required.

## What works

- **Local encrypted vault**: Argon2id passphrase, recovery key shown once and confirmed,
  passphrase change, recovery-key rotation, auto-lock after five minutes idle and on exit.
  Format specified in `docs/crypto-format.md` with known-answer vectors from independent code.
- **Encrypted backup and restore**: one file, opens with the vault's passphrase or recovery
  key; restore validates every item before replacing anything.
- **Quick unlock** with the OS keychain (macOS Keychain, Windows Credential Manager, Secret
  Service on Linux), off by default; never falls back to storing anything in plain text.
- **SSH**: explicit first-use host-key decision, changed keys blocked before any credential is
  sent, known-hosts management with a reason for every removal; password, stored password,
  keys (Ed25519, ECDSA, RSA with SHA-2 only; encrypted keys with optional remembered
  passphrase), keyboard-interactive (one-time codes, PAM); the negotiated cipher and key
  exchange are shown; dropped connections reconnect with capped backoff.
- **Terminal**: GPU (WebGL) rendering with automatic fallback, 14 color schemes, font and
  cursor settings, ligatures (optional), search, zoom, 256 and 24-bit color, wide and combining
  characters, IME, mouse, alternate screen; links open only after confirming the real
  destination (http/https only); clipboard writes from the server need per-session consent
  and reads are never answered; multi-line and large pastes are previewed.
- **Workspace**: home with recent connections and quick connect, hosts grid/list, command
  palette (⌘K / Ctrl+Shift+K), tabs (rename, reorder, close), split panes, local terminal.
- **Snippets**: encrypted, in folders, from a side panel that always shows which session it
  sends to; Run and Paste are sent by the core from the vault; nothing runs automatically.
- **Themes**: light, dark and system, checked for WCAG 2.2 AA contrast; reduced motion.

## How it was tested

Evidence: native workflow run 38216895650 on commit `da60796` (and the release workflow re-runs
every suite on the tagged commit before it builds anything). On each of the three platforms:
fast checks 7/7, integration 3/3, security 6/6, native end-to-end 4/4 suites, 0 blocked; the
unsigned release build and the release-policy check against the built binary passed. The
browser UI suite, cargo-deny, npm audit, the full-history secret scan and the fuzz smoke run
passed on the same commit. 24 feature-matrix rows are VERIFIED on this commit; six more are
implemented but not verified (UI-only tests, or a missing piece named in the matrix).

Every platform above ran, in CI, against a real OpenSSH server started for the run (never a
real server or real credential): format/lint/type checks and all Rust tests; SSH adapter and
core session suites; security suites (vault tampering, storage permissions, host-trust order,
session ownership); and the real application end to end over WebDriver (vault, hosts, keys,
first connection, lock, restart, changed host key, terminal with vim, nano, tmux, htop and mc,
colors, resize, a hostile escape-sequence corpus, snippets, backup and restore). Browser UI
behavior and visual regression tests ran in a pinned Playwright image. Security workflow:
cargo-deny, npm audit, full-history secret scan, fuzzing smoke run of the vault decoders.

Lab servers: the Linux client used Ubuntu 24.04's OpenSSH 9.6p1; the Windows client used
Debian 12's OpenSSH 9.2p1 inside WSL 1 (so the Windows run also covers PAM keyboard-interactive
and the full-screen applications); macOS used the runner's own OpenSSH.

## Known issues and limits

- Not independently security reviewed; vault format version 1 has no rollback protection for
  someone who can write the database file (see `docs/crypto-format.md` §8).
- Unsigned and not notarized. No automatic updates.
- Idle memory and warm launch miss their budgets on the measured machine.
- The vault does not yet lock when the OS screen locks (it locks on sleep, after five idle
  minutes and on exit).
- Terminal search, zoom settings and clipboard-write consent are tested in the browser UI suite
  only, not yet end to end in the native app.
- Keyboard-interactive answers and passwords are copied once into the SSH library, which does
  not zeroize them.
- The IPv6 loopback test runs only where the host has IPv6.

## Not implemented yet

SFTP, port forwarding and jump hosts, host groups/tags/identities and imports (in progress for
the next pre-release), saved workspaces and broadcast input, session logs, sync, mobile apps,
X11 forwarding (not planned).
