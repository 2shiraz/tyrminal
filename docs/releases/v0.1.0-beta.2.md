# Tyrminal v0.1.0-beta.2 — pre-release

> **This is a pre-release for testing, not a stable or production-ready version.**
> It has **not been independently security reviewed**. The installers are **unsigned**. Use it
> with test servers and test credentials. There is no automatic updater.

Tyrminal is a local-first SSH client: an encrypted vault on your device, verified host keys,
and a modern terminal. No account, no cloud, no telemetry.

## New since beta.1

- **Host inventory**: groups, tags, search, duplicate, bulk edit, identities; import from
  OpenSSH config and CSV; deploy a public key to a server (creates `~/.ssh` and
  `authorized_keys` with owner-only permissions).
- **Broadcast input** to several sessions, always showing which sessions receive it.
- **SFTP file manager** (side panel, Ctrl/⌘+Shift+O): browse, create folders, rename,
  permissions, delete; upload and download files and whole folders; two-pane view of this
  computer and the server with drag and drop; copy files and folders between two servers.
  Transfers are written to a temporary name and renamed only when complete, so a cancelled or
  failed transfer never leaves a partial file. On a name clash you choose Replace or Keep both;
  folders are never merged or replaced. Tested byte for byte up to 2 GiB with bounded memory.
- **Edit a remote file** in a local application: saving uploads only when you click Save, and
  refuses if the file changed on the server meanwhile. Per-extension editor choices are picked
  with the system app chooser only.
- **Vault locks when the OS screen locks** (macOS, Windows, and Linux desktops that report it
  over D-Bus).
- **Choose the shell** for local terminals from the shells installed on the computer.
- **Accessibility**: an automated axe-core audit covers the lock, onboarding, main pages and
  terminal panels in both themes.

## How it was tested

Before merging, every change ran the full CI on its own commit: on macOS (Apple Silicon),
Windows x64 and Linux x64 the fast checks, integration and security suites against real
OpenSSH lab servers, and the real application end to end; plus the browser UI suite,
cargo-deny, npm audit, the full-history secret scan and a fuzzing smoke run. The SFTP suite
includes a 2 GiB round trip checked byte for byte on macOS and Linux, a connection dropped in
the middle of a transfer, and server-side changes made while a file is open for editing.
The feature matrix (`docs/feature-matrix.csv`) lists which rows are VERIFIED, with the commit
and test names; rows that are implemented but not verified say so.

Every platform ran, in CI, against real OpenSSH servers started for the run (never a real
server or real credential), and the release workflow re-runs every suite on the tagged commit
before it builds anything.

## Known issues and limits

- Not independently security reviewed; vault format version 1 has no rollback protection for
  someone who can write the database file (see `docs/crypto-format.md` §8).
- Unsigned and not notarized. No automatic updates.
- Idle memory and warm launch missed their budgets when measured for beta.1 (not re-measured).
- Screen-lock detection on Linux depends on the desktop publishing a lock signal on D-Bus.
- Dropping files from the desktop onto the file panel is not supported yet (use Upload or the
  two-pane view).
- Keyboard-interactive answers and passwords are copied once into the SSH library, which does
  not zeroize them.

## Not implemented yet

Saved workspaces and layouts, session history and logs, sync, mobile apps, X11 forwarding
(not planned).
