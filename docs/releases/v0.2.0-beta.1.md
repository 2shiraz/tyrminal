# Tyrminal v0.2.0-beta.1 — pre-release

> **This is a pre-release for testing, not a stable or production-ready version.**
> It has **not been independently security reviewed**. The installers are **unsigned**. Use it
> with test servers and test credentials. There is no automatic updater.

Tyrminal is a local-first SSH client: an encrypted vault on your device, verified host keys,
and a modern terminal. No account, no cloud, no telemetry.

## What's new since v0.1.0-beta.1

### A new interface
- **Hosts, redesigned**: a search bar at the top that also connects (type an address and press
  Enter), groups as sections, favourites, list and card views, OS icons, and a details side
  panel that slides in. Arrow keys move between hosts; a click selects, a double click or Enter
  connects; the selection's context menu carries the bulk actions.
- **Browser-style tabs** that resize together, with a **new-tab page** behind "+": search hosts,
  open a local shell, SFTP or serial, and reopen recent connections. Quick connect opens in its
  own tab.
- **Resizable side panels** and **interface scaling** for high-resolution displays.
- **Motion** that follows the pointer and never the keyboard, with reduced-motion respected.
- Home is gone: everything it offered lives on Hosts and the new-tab page.
- App chrome no longer selects or underlines like a web page, and the WebView's own right-click
  menu is replaced by Tyrminal's menus.

### Terminal and sessions
- Command-finished notifications for long commands in background tabs, unread marks on tabs
  with new output, search across every open session, and saving a marked command's output.
- Notes on hosts and groups (inert Markdown, stored in the vault).
- Session recordings and command history (recordings are **off by default**).
- Workspaces and layout templates; duplicate a tab into a new session.
- Faster start: about 190–210 ms cold start, and the first screen needs fewer than half the
  calls it used to.

### Security fixes
- RSA signatures with a leading zero byte are now padded to the key size, so some RSA keys no
  longer fail to sign in intermittently.
- Servers that ask for more than one sign-in step (partial success, for example key then
  password) are now supported.

### Inventory, connections and files

- **Host inventory**: groups, tags, search, duplicate, bulk edit, identities; import from
  OpenSSH config and CSV; deploy a public key to a server (creates `~/.ssh` and
  `authorized_keys` with owner-only permissions).
- **Broadcast input** to several sessions, always showing which sessions receive it.
- **SFTP file manager** (side panel, Ctrl/⌘+Shift+O): browse, create folders, rename,
  permissions, delete; upload and download files and whole folders; two-pane view of this
  computer and the server with drag and drop; copy files and folders between two servers.
  Transfers are written to a temporary name and renamed only when complete, so a cancelled or
  failed transfer never leaves a partial file. On a name clash you choose Replace or Keep both;
  folders are never merged or replaced. Tested byte for byte up to 2 GiB with bounded memory.
- **Edit a remote file** in a local application: saving uploads only when you click Save, and
  refuses if the file changed on the server meanwhile. Per-extension editor choices are picked
  with the system app chooser only.
- **Vault locks when the OS screen locks** (macOS, Windows, and Linux desktops that report it
  over D-Bus).
- **Choose the shell** for local terminals from the shells installed on the computer.
- **Accessibility**: an automated axe-core audit covers the lock, onboarding, main pages and
  terminal panels in both themes.
- **Port forwarding**: local, remote and dynamic (SOCKS5) tunnels, saved per host and started
  on a connected session, or automatically with every connection. Listeners stay on this
  computer's loopback unless you confirm, separately, that other computers may reach them.
  A tunnel stops, and its port closes, when its session ends for any reason.
- **Tunnels page** listing saved rules and running tunnels with open and total connections and
  traffic. Stop, edit and duplicate rules there.
- **Jump hosts**: connect through one or more saved hosts (up to eight in a chain). Every hop's
  host key is checked, and you sign in to it, before anything is sent to the next one. A changed
  key on any hop stops the connection. Trust and password prompts say which hop is asking.
- **Proxies**: reach a host through an HTTP CONNECT or SOCKS5 proxy, with an optional user name
  and password. The proxy password is stored in the vault and never shown again. The server's
  key is still checked end to end, so a proxy cannot pose as the server.
- **Telnet and serial hosts**: choose SSH, Telnet (with a warning that it is unencrypted) or a
  serial device on this computer (baud, data bits, parity, stop bits, flow control).
- **Character encoding and terminal type per host**: UTF-8, ISO-8859-1/15, Windows-1252,
  KOI8-R, Shift_JIS, EUC-JP, EUC-KR, GBK, GB18030, Big5; xterm-256color, xterm, linux, vt220,
  vt100.
- **SSH agent forwarding**, off by default: only the host's own sign-in key is offered, the
  server can only list and sign, and every signature is shown in the session.
- **Drop files onto the file panel** to upload them; files arrive under a temporary name and
  appear only when complete.
- **Create a host from Known hosts** for a trusted server that has no saved host yet.
- **Diagnostics report** (Settings, off by default): a list of recent command names and error
  codes you can save and attach to a bug report; never hosts, names or secrets.

## How it was tested

Before merging, every change ran the full CI on its own commit: on macOS (Apple Silicon),
Windows x64 and Linux x64 the fast checks, integration and security suites against real
OpenSSH lab servers, and the real application end to end; plus the browser UI suite,
cargo-deny, npm audit, the full-history secret scan and a fuzzing smoke run. The SFTP suite
includes a 2 GiB round trip checked byte for byte on macOS and Linux, a connection dropped in
the middle of a transfer, and server-side changes made while a file is open for editing.
The feature matrix (`docs/feature-matrix.csv`) lists which rows are VERIFIED, with the commit
and test names; rows that are implemented but not verified say so.

Every platform ran, in CI, against real OpenSSH servers started for the run (never a real
server or real credential), and the release workflow re-runs every suite on the tagged commit
before it builds anything.

## Known issues and limits

- Not independently security reviewed; vault format version 1 has no rollback protection for
  someone who can write the database file (see `docs/crypto-format.md` §8).
- Unsigned and not notarized. No automatic updates.
- Idle memory and warm launch missed their budgets when measured for beta.1 (not re-measured).
- Screen-lock detection on Linux depends on the desktop publishing a lock signal on D-Bus.
- Keyboard-interactive answers and passwords are copied once into the SSH library, which does
  not zeroize them.
- A tunnel's loopback port can be used by other accounts on the same computer, as with
  OpenSSH. The SOCKS proxy does not ask for a user name or password.
- An HTTP proxy receives its user name and password base64-encoded, not encrypted.

## Not implemented yet
